# 收藏文章 → Kindle epub（免确认直推，收藏保留）

与「未读转 Kindle」同构，差异：数据源是收藏（starred），推送不改变服务端任何状态（收藏保留、不标已读，只读令牌即可）。

## 前置检查

1. `x6o4 status` 可用（不可用则引导用户终端运行 `x6o4 login`，用户亲自输密码）。
2. 权益无效则如实告知并终止。

## 执行流程（无需逐项确认）

1. **取收藏**（可按用户话语限定范围，如「最近一个月的」）：
   ```
   x6o4 entries --starred --limit 100 --print --out /tmp/x6o4-fav.json
   ```
   用户说了时间范围的，拉取后按 `published_at` 过滤；没说则全量分批处理。批量很大时，筛选用的元数据与摘要直接读 `--out` 文件（完整数据都在文件里；Git Bash 只在路径作为命令参数时才转换 `/tmp`，node 或 Python 脚本内部读这个文件要用 `process.env.TEMP` 拼路径，或先用 `cygpath -w` 换成 Windows 路径；评估脚本本身用 Write 类工具落盘时同样不要写 `/tmp`——这类工具不做 MSYS 路径转换，`/tmp` 会落到当前盘符根目录的 tmp（如 `D:\tmp`），与 Bash 里的 /tmp 不是同一目录）；`--print` 的屏幕输出不要经管道转存或直接在终端查看——Windows 终端编码会把中文变成乱码。
2. **筛与定量**：收藏本身就是用户的选择，一般不做语义剔除；数量多时按发布时间倒序分批（单册建议 ≤50 篇，命令行会自动分册），先处理最近的一批，向用户说明剩余量。
3. **生成与发送**（不传 `--out` 与 `--title`：文件名与书内书名自动统一为「RSS 阅读-当天日期-首篇标题 等N篇」，首篇标题过长会截断、多册时末尾加（一）（二），同批重复生成同名覆盖。epub 生成在**运行命令的当前工作目录**——不是 /tmp；完成行「→」后面是文件完整路径，`--file` 原样使用它、不要自己构造文件名或通配符——通配符里的中文经 Windows 命令管道传递可能编码错乱、匹配不到文件。邮件主题默认取文件名）：
   ```
   x6o4 build-epub --ids ... --from /tmp/x6o4-fav.json
   x6o4 send-kindle --file <实际文件1> --file <实际文件2>
   ```
   多批合并生成时 `--from` 重复传入、每批一个参数（Git Bash 下逗号分隔的路径列表不会被自动转换成 Windows 路径，详见未读技能第 4 步）；多册同理重复传 `--file`。构建输出含「全文拉取」统计（摘要源自动拉原文、防盗链图片自动分级下载；没有需要拉取的会显示「无需拉取」）。本技能持只读令牌，无法执行 `feeds config` 保存按源设置——统计行尾列出可保存的源时，在汇报中提示用户（改用读写令牌登录后由未读推送技能自动保存，或在网页管理页手动开启）。
   书的语言按用户的交流语言决定：用户用英文交流时，上面两条命令都加 `--lang en`——书内固定文字（来源/作者/发布/目录/原文链接等）、默认书名与邮件正文会是英文；用户用中文交流或无法确定时不加，工具按系统环境自动判断（输出里的「文案语言 / Text language」行是判定结果）。`--lang` 同时切换该次运行的**全部终端输出**语言（完成行、错误提示等，英文含义与中文一致）；不加时输出语言跟随用户配置（登录时选过）或系统环境，中英文都可能出现，同样按语义理解。
4. **不调用 mark-read、不取消收藏**——推送后服务端状态不变。

## 事后汇报

推送清单（标题 + 来源）、分册情况、失败明细；提醒还有多少条收藏未处理，用户可再说「继续推下一批」。

## 失败处理与铁律

同「未读转 Kindle」技能：错误完整呈现；正文、令牌、授权码不进对话；Kindle 邮箱需国际区 @kindle.com 且发件地址已加亚马逊认可列表。配置 `mail_transport` 为 `agently` 时无授权码，发送问题按该技能「失败处理」里的 agently 条目处理。

## 退出与收回授权

用户说「退出 RSS Cloud」「收回授权」「切断权限」这类话时，运行 `x6o4 logout`：吊销本机令牌在服务端的授权并清除本地保存，把命令输出如实转述给用户。若提示未知命令（旧版本工具），先运行 `npm update -g x6o4-tools` 升级后重试。
