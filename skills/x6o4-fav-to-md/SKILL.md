# 收藏文章 → Markdown（幂等导出，收藏保留）

## 前置检查

1. `x6o4 config check`：需要 `obsidian.vault_dir`（笔记库目录）。缺了就问用户要路径，写入 `~/.x6o4-tools/config.json` 的 `obsidian.vault_dir` 字段后再继续（其余配置不动）。
2. `x6o4 status` 可用（不可用则引导用户终端运行 `x6o4 login`）。
3. 权益无效则如实告知并终止。

## 执行流程

1. **取收藏**（可按用户话语限定范围）：
   ```
   x6o4 entries --starred --limit 100 --print --out /tmp/x6o4-fav.json
   ```
   （`--print` 输出元数据与摘要供你向用户复述清单；正文留在文件里，转换由程序完成。）
2. **导出**（幂等：已导入的来源链接自动跳过，重复执行零副作用）：
   ```
   x6o4 export-md --from /tmp/x6o4-fav.json [--since 2026-01-01]
   ```
3. **汇报**：新增 X 篇、跳过 Y 篇（已导入）、失败清单（如有）；收藏状态不变。
4. **（可选，仅用户明确提出时）AI 润色/摘要**：用户要求「给重点文章写摘要/修一修格式」时，直接编辑生成的 Markdown 文件——保留原文链接（知识库要溯源）、保留表格与代码块、清理无意义空行；逐篇读正文前先估量篇幅，长文较多时提醒用户分批。默认不做。

## 分批

收藏很多时按 `published_at` 倒序分批（每批 100），每批一条 export-md 命令；完成后告诉用户剩余量。

## 失败处理与铁律

- 错误完整呈现，不静默吞掉；文件写入失败（路径不存在/无权限）时如实报告。
- 正文不进对话（除非用户明确要求润色的那些篇）；令牌与授权码不进对话。
- 不调用 mark-read、不取消收藏——导出后服务端状态不变。
