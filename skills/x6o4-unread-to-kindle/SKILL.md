# 未读文章 → Kindle epub（免确认直推）

## 前置检查（每次运行第一步）

1. 确认命令行可用：`x6o4 status`（npm 全局安装：`npm install -g x6o4-tools`；未安装时也可 `node <仓库路径>/cli/x6o4.js status`）。
2. 若报「配置未就绪」或令牌无效：引导用户在**终端亲自**运行 `x6o4 login`（交互式长命令，用户亲自输入邮箱密码，你不要代输、不要索要密码）；登录成功后再继续。
3. 若 status 显示权益无效（SUBSCRIPTION_*）：如实告诉用户需要续订或领取试用后才能读取文章，终止本次。

## 执行流程（全程无需向用户逐项确认）

调用即授权：用户让你推 Kindle，就是发送与标记已读的授权。正文永不读入对话，只依据元数据与摘要判断。

1. **取候选**（元数据 + 160 字摘要进对话，全文留在本地文件）：
   ```
   x6o4 entries --status unread --order published_at --direction asc --min-reading-time 3 --limit 100 --print --out /tmp/x6o4-unread.json
   ```
   （Windows 用 `%TEMP%` 等临时目录；下同。被 30 天本地跳过记录排除的条目不会出现。）
2. **语义细筛**：依据标题、来源、时长、摘要剔除不适合 Kindle 长阅读的——公告/通知、视频集合、纯图集、快讯短讯、招聘/广告帖。用户在对话里给过偏好的按偏好来。
3. **定量**：按发布时间从旧到新取前 N 篇（N = 配置 `unread.max_articles_per_run`，默认 20，取满即止；不足有多少发多少；筛完 0 篇则不发不标，直接汇报「没有适合的内容」）。生成与阅读顺序同为从旧到新。
4. **生成 epub**（不传 `--out` 与 `--title`：文件名与书内书名自动统一为「RSS 阅读-当天日期-随机文章标题」，Kindle 与各阅读器显示一致；从命令输出的文件路径取实际文件名）：
   ```
   x6o4 build-epub --ids 9001,9002,... --from /tmp/x6o4-unread.json
   ```
   输出中的「全文拉取」行统计摘要源处理情况（配置/启发式/失败保留原文），防盗链图片也会自动分级下载，无需任何参数。
5. **持久化发现的摘要源**（仅当上一步「全文拉取」行尾列出「可保存拉取原文设置的源」时执行，逐个编号；没有则跳过本步）：
   ```
   x6o4 feeds config --id <源编号> --full true --referer false
   ```
   把「拉取原文」保存到服务端（App 与网页管理页共用同一份设置，后续运行不再依赖启发式）；失败不阻断本次推送。
6. **发送**（自动，一封邮件带全部分册；文件用上一步输出里的实际路径，邮件主题也默认取文件名）：
   ```
   x6o4 send-kindle --file <实际文件1>[,第2册,...]
   ```
7. **标记已读**（仅实际进入 epub 的条目；发送受理后自动执行）：
   ```
   x6o4 mark-read --ids 9001,9002,...
   ```
8. **记入跳过记录**（被筛掉的文章 30 天内不重复筛）：
   ```
   x6o4 skip add --ids <被筛掉的编号>
   ```

## 事后汇报（唯一的用户交互）

一次性汇报：已推送 N 篇（清单：标题 + 来源 + 阅读时长）、筛掉 K 篇（各附一句理由）、已标记已读 M 篇、全文拉取统计（配置 X / 启发式 Y / 失败保留原文 Z，及已持久化的源）、失败明细（如有）。用户说「把某篇也推给我」时：从 /tmp/x6o4-unread.json 取该篇 → 重复步骤 4–7，并从跳过记录恢复（该篇不在 skip 里就不会再被排除）。

## 失败处理

- 任何命令失败：完整呈现错误原文（错误信息已含中文指引），不要静默吞掉、不要盲目重试。
- 发送失败（授权码失效/未加白名单）：提示两个前提——SMTP 发件地址需加入亚马逊「认可的发件人」列表；亚马逊中国区个人文档服务已停运，需国际区 @kindle.com 邮箱。epub 已在本地，可数据线拷贝或 Send to Kindle 网页版上传（200MB）兜底。
- 配置 `mail_transport` 为 `agently` 时（用 agent mail 产品的 agently-cli 发信，无授权码；agent mail 是腾讯的独立邮箱产品，不是 QQ 邮箱）：报「未找到 agently-cli 命令」提示先 `npm install -g @tencent-qqmail/agently-cli`；报未登录则引导用户在终端亲自运行 `agently-cli auth login`（浏览器授权，用户亲自完成，不要代操作）。
- 令牌 401：引导重新 `x6o4 login`。

## 铁律

- 正文与令牌/授权码不进对话；status 只显令牌前缀。
- 只标记实际进入 epub 的条目；被筛掉的保持未读。
- 不新增任何事前确认环节（用户的话就是授权）；只有指令未覆盖的破坏性动作（清空收藏、吊销令牌等）才需要确认。
